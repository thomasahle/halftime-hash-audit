# Second independent review of the HalftimeHash paper (author-run, 2026-09-18) — condensed
Scope: the paper's mathematics only (explicitly not the implementation; assumes the claimed code distances).
- Lemma 3 gap confirmed with the same (0,0)/(1,0) witness; page-8 "mε^k" should be (mε)^k.
- Theorem 1: p used as power and as exponent; missing division by 2^{p'} (the congruence Z ≡ β mod 2^{64−p'} is false as written); equality should be ≤. Repaired adjugate bound P^k 2^{-32k}; stronger kernel-count (Smith normal form) bound 2^{t−32k}.
- Exact minors of all four displayed matrices (441 maximal minors, integer arithmetic): no zero determinants; max v2 = 2, 2, 3, 3 for the 2×7, 3×9, 4×10, 5×9 matrices (examples: cols (0,5) det 4; (0,1,3) det 12; (0,1,5,6) det −24; (0,1,2,4,8) det −8). EHC-only bounds 2^-62, 2^-94, 2^-125, 2^-157.
- Replacement end-to-end bound (subset/minor method, identical to our review §3.2–3.3): HalftimeHash16 2^-64(h+2)(h+5); HalftimeHash24 2^-96(h+2)^2(h+5) (subset sums 6, 9, 4); HalftimeHash32 2^-128(h+2)^3(h+9); HalftimeHash40 2^-160(h+2)^4(h+9). At h = 16 (exabyte) HalftimeHash24 gives 6804·2^-96 → 83.27 bits: the ">83 bits" claim is recoverable under the construction assumptions, not via the printed formula (literal p=4 gives 82.9998; valuation t=2 gives 83.977).
- Paper errata: Eq. (3) output-length mismatch (should be floor(lg n)+1 slots); n in 32-bit words (§2) vs b in 64-bit words (§6.1): EHC group count should be floor(n/(2bdw)); forest root count is S_f(N) ≤ (f−1)(h+1), not ≤ fh (N=63, f=8 gives 14 roots vs 8), so the bfhk final-NH budget does not cover every forest; tree multiplications kb(N − S_f(N)); seed-size expression evaluates to 197+213h words (6,688 B at 1 MB, 28,840 B near an exabyte) vs stated 8.4 KB / 34 KB; "84% of multiplications" matches HalftimeHash40 (27/32), not HalftimeHash24 (27/30 = 90%); Definition 1 lacks x ≠ y; pigeonhole/det wording on p. 5; intro's O(n^{2−c}) needs ε = O(n^{−c}).
- Sound: Lemma 1 (as an upper bound), NH + un-hashed last pair (Badger), matrix divisibility claims.
- Not covered by this review (ours covers it): the shipped Encode3 does not have distance 3 (executed witness); the public 24-byte API's advertised bound is refuted (ε ≥ 2^-32 when high32(core_key[6]) = 0; independent execution check in progress); the shipped 64-bit wrappers certify 63 bits with overlapping keys; TabulateAfter out-of-bounds subscript; NEON dispatch build failure (issue #1, PR #2 filed).
